# ADR-053：Desktop 运行目录与安装管理分离

开发、主链路验收和日常使用复用同一 Desktop Host、原生 UI 与退出事务（ADR-033/037/052）。DesktopBootstrap 在读取配置或创建日志前确定 Profile 并取得目录独占权；安装集成单独绑定自启动和更新能力。选择这一边界，是因为拆成常驻服务与独立 UI 仍需解决目录和安装所有权，还会引入 IPC、版本配对及双进程更新，目前没有必须独立重启 UI 的需求。

Profile 复用原有数据布局。不同 Profile 可并行，同一实际目录（包括路径别名）只能有一个运行者；runId 与版本不参与目录身份，也不改变真实 Machine Subject。显式 `--data-directory` 和启动 smoke 都是独立运行，即使执行已安装制品也无安装管理能力。正常启动只有经 Velopack 确认已安装的制品才绑定当前安装；DesktopState 构造及读取不得修改安装注册。

独占通过目录内保持打开的 `.desktop.lock` 实现，运行期间不得删除或替换该文件。默认目录同时持有旧版 Mutex，兼容引入本 ADR 之前的 Desktop 制品。只有最低支持版本已经包含目录独占、且默认目录升级和跨进程互斥回归通过后，才可移除旧 Mutex；此前目录锁不能替代对旧版的保护。锁建立失败必须停止启动。

验收器独立选择源码构建或既有制品，再执行相同场景，记录版本与整个制品目录的 hash。Profile 主链路验收不替代 Setup、安装更新、自启动及操作系统权限的设备验收（ADR-039/048）。
