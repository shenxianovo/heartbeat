## Problem Statement

Heartbeat 的退出重构已由 00806ad 落地，但正常运行时的能力变更、原生 session、管理操作与数据交付仍依赖跨模块时序。管理界面关闭可能影响已接受操作，旧 native session 可能与新 session 共享资源。

## Solution

每个运行子树管理自己的状态和资源。UI 提交命令并读取结果；Host 保管已接受的操作。配置按最新意图串行收敛。Desktop 与 Headless 共享运行职责，保留各自的主体投影。数据交接提供可判定结果。

## User Stories

1. 作为用户，我希望切换能力立即按当前可用条件生效，不增加合并等待。
2. 作为用户，我希望快速反复切换能力时最终状态符合最新配置。
3. 作为用户，我希望旧原生会话的回调和清理不会影响新会话。
4. 作为用户，我希望权限撤销只暂停受影响能力，启用意图仍保留。
5. 作为用户，我希望某个 Collector 故障不影响其他 Collector。
6. 作为用户，我希望安装被 Host 接受后不随管理界面关闭或浏览器断线而取消。
7. 作为用户，我希望重新进入管理界面能够查看当前 Host 中的操作结果。
8. 作为用户，我希望取消有明确结果，不能撤销的阶段也能得到清楚反馈。
9. 作为用户，我希望重启后恢复已经保存的配置和安装事实，并可以重新发起未提交操作。
10. 作为用户，我希望 Desktop 与 Headless 的安装、运行和停止遵守同一契约。
11. 作为用户，我希望暂停、故障和停止时未交付数据的保管责任可判定。
12. 作为用户，我希望应用退出后不会再接受冲突变更，最终副作用只执行一次。

## Implementation Decisions

- 已确认决定的权威来源为 ADR-052；本 PRD 把决定组织成实施切片。
- 每项能力串行协调最新目标，不维护配置历史队列，不引入 debounce。运行中转换先完成安全交接，再读取最新目标。
- 原生会话独立持有线程、句柄和回调身份；未确认结束的会话不能被当作已释放。
- 管理操作由 Host 接受、执行、保存结果；请求取消与已接受操作取消分离。
- 已接受操作在安全撤销阶段支持明确取消，不可撤销阶段继续收尾并返回不可取消。
- 进程重启仅恢复已持久化的配置和安装事实，不承诺任务历史和断点续装。
- Host 只编排子树，各子树内部资源不得泄漏给 UI。保留既有 Account/Machine Subject 差异。
- 数据责任通过现有协议与存储接口汇总，保留未知状态，不把 Stop 成功推断为持久化成功。

## Testing Decisions

使用用户已确认的行为边界：采集能力公开控制接口与观察输出；Host 管理命令和结果查询；真实 Host 组合；已有 Fact/Upload 交接接口；应用退出接口。先稳定复现再修复，每次一条完整行为。原生竞态用可控适配器/阻塞点验证，真实 OS 权限和打包更新作为人工验收记录。每片完成执行对应回归；跨项目变更执行全量 .NET 回归。以 00806ad 为初始审查基线，实施后做 Standards/Spec 双轴审查。

## Out of Scope

微服务化、全局事件总线、持久任务队列、跨重启操作历史、断点续装、重写 Analytics/Dashboard 领域模型。退出期限、失败交互与更新提交策略仍按 ADR-052 后置，不能据此宣称产品行为全部验收。
